# Marketing site i18n

Framework for locale-specific copy on the ContextMint marketing site (Eleventy). English and Arabic packs ship under `src/_i18n/en/` and `src/_i18n/ar/`. New body-wired pages must provide **both** locale packs or `/ar/…` falls back to English (`lang=en`).

## Layout

```text
src/_i18n/
  locales.json          # catalog (en + ar declared; ar inactive until folder exists)
  en/
    common.json         # nav, footer, announcement, a11y chrome
    home.json           # per-page pack (title/description minimum)
    about.json
    ...
  ar/                   # folder present → selector + /ar/ URLs (English until packs added)
    .gitkeep
    common.json         # add to unlock Arabic chrome+pages (with page packs)
    home.json
    ...
```

## Activation rules

1. Default locale is always `en` at `/…`.
2. A non-default locale (e.g. `ar`) becomes **active** when `src/_i18n/{code}/` exists.
3. Active locales are paginated automatically (`/{code}/…`).
4. **All-or-nothing per page:** for a non-default locale, both `common.json` and the page pack (e.g. `about.json`) must exist. If either is missing, that URL still builds but uses **full English** (chrome + page pack) — never mixed Arabic chrome with English page body.
5. Language selector appears when more than one **locale folder** is active (not merely listed in `locales.json`).
6. An empty locale folder (e.g. `ar/` with only `.gitkeep`) is enough to show the selector and build `/{code}/…` URLs; every page stays **full English** until both `common.json` and that page’s pack exist.

## What is wired today

| Source | Used for |
|--------|----------|
| `common.json` | Nav, footer, announcement, skip link, language label, **docs sidebar** |
| Page pack `title` / `description` | Document `<title>` and meta description |
| Page body keys (e.g. `hero.*`) | Where the HTML template reads `i18nPageStrings` |

**Fully body-wired pages (en + ar):** all marketing pages (Home, About, Features, Pricing, FAQ, Roadmap, Getting started, Trust, Support, Support/Troubleshooting, Design partners, Request demo, Accessibility, Privacy, Terms, 404, `product/*`, `solutions/*`); **all `docs/*` pages** (index, installation, chat-and-lanes, image-evidence-argus, context-lens-packs, engine-operator, indexing-readiness, patches-governance, knowledge-and-governance, settings, context-budget-calculator, byok-enterprise, sovereign-server, glossary); **all `developers/*` pages** (index, cli, mcp-server, api-reference).

Shared marketing includes (`cta-band.html`, `powered-by.html`, `product-screenshots.html`, `roadmap-planned-banner.html`, `jargon-verification.html`, `verification-badge.html`, `support-escalation.html`, `support-nav.html`) read their default copy from `i18nCommon` and use `locale_path` for internal links, so they localize automatically on any page that includes them.

**`docs/context-budget-calculator.html` JS strings:** the interactive calculator's JS-rendered labels, table headers, and advisory warning copy live under the page pack's `js` key and are shipped to the browser via `<script type="application/json" id="budget-i18n">{{ t.js | json }}</script>`. The inline script reads that JSON, falls back to the English literal if a key is missing, and uses a small `fmt(template, vars)` helper for `{token}` interpolation — so warning/label text renders in the active locale without duplicating the calculator's numeric logic.

**By design (not page-pack i18n):** `docs/settings.html` **settings catalog** row descriptions (from `extensionSettings.json` / `serverChatSettings.json`) stay English — operator-facing generated config metadata. Page chrome (tabs, labels, search, usage-guide narration) is localized.

**Important:** Hardcoded English in an `.html` file will not change when you edit the JSON. Prefer `i18nPageStrings` + `locale_path` for new marketing/docs copy.

## Adding Arabic copy

1. Ensure `src/_i18n/ar/` exists (activates selector + `/ar/` URLs).
2. Provide **both** `common.json` and the page pack (e.g. `home.json`) — all-or-nothing.
3. Mirror keys from `en/<page>.json`; translate **values** only.
4. Rebuild and open `/ar/…` (hard refresh).

## Template helpers

- `{{ i18nCommon.nav.product }}` / `{{ "nav.product" | t }}`
- `{{ "/about.html" | locale_path }}` — prefixes `/ar` when rendering a locale URL
- `htmlLang`, `htmlDir`, `localePrefix`, `i18nBundle.fallback`

## Regenerating English page meta packs

```bash
node scripts/gen-i18n-en-page-packs.mjs
```

Overwrites `src/_i18n/en/*.json` title/description from page front matter (does not touch `common.json`).
