BYOK & enterprise deployment

Default ContextMint is local-first: code and indexes stay on your machine. Teams that need shared infrastructure or approved cloud models enable optional paths below — all off by default.

Local-first (default)

  • Engine + Ollama on loopback
  • API keys not required
  • No egress of source code for indexing or local inference

BYOK cloud routing

When platform policy allows external inference:

  1. Enable contextmint.trust.cloudEnabled
  2. Run command ContextMint: Configure Cloud API Key
  3. Keys stored in VS Code SecretStorage — never in Engine config or server logs
  4. Select Cloud or Auto in compose model picker

Only redacted assembled context is sent to the provider you choose. Routing badge and inspector show cloud tier when used.

Cloud vision (optional multimodal)

When cloud routing is enabled, you may explicitly select a cloud vision-capable model for messages with image attachments. Images are not automatically sent to the cloud when you attach them — local Ollama vision remains the default even if API keys are configured.

  • Multimodal parts are assembled in the extension; keys stay in VS Code SecretStorage
  • Supported providers include OpenAI- and Anthropic-compatible vision APIs when configured
  • ARGUS visual audit defaults to local vision — independent of cloud chat keys

Details: Image evidence & ARGUS.

Shared on-prem API server (pilot)

Platform team deploys Docker/Helm stack; developers configure:

  • contextmint.server.serverUrl — HTTPS internal hostname
  • contextmint.trust.enterpriseMode — true when auth required
  • OIDC provider ID and JWT validation on server

Extension does not install Engine. Workspace paths on the server must match what developers open in VS Code (Remote SSH workspace folders or consistent mount paths).
